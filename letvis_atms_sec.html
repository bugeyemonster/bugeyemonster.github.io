Expert Security Assessment Plan

LETVIS Air Traffic Management System

This assessment plan outlines a rigorous, non-intrusive security evaluation for the LETVIS Air Traffic Management (ATM) system. As critical infrastructure, the assessment prioritizes operational safety, system integrity, and availability, guided by NIST and ICS-specific standards. This interactive view allows you to explore the plan's objectives, scope, and methodology.

Assessment Objectives

  • Identify security gaps against industry standards (NIST SP 800-82, RTCA DO-326A).
  • Focus on vulnerabilities impacting data integrity and system availability.
  • Ensure zero interference with live air traffic control operations.
  • Deliver an evidence-based, "snap-shot" evaluation of the current security posture.

A zero-impact assessment in a live ATM environment requires specialized, passive data collection techniques. The methodology relies on three pillars: capturing network traffic non-intrusively, reviewing configurations and logs, and conducting structured interviews with system owners to validate processes.

Data Collection Pillars

Network Packet Analysis

Passively capture and analyze traffic from TAPs or SPAN ports to map data flows and find protocol anomalies without sending a single packet.

  • Wireshark/Tshark
  • Zeek (NSM Framework)
  • Malcolm / Arkime
  • ASTERIX Protocol Analysis

Config & Integrity Validation

Review system hardening, patch status, and file integrity logs to validate the "known good state" of COTS components.

  • Ansible (Check Mode)
  • Nessus Scan Reports (Credentialed)
  • File Integrity (FIM) Logs
  • Syslog / SIEM Review

System Owner Interviews

The primary method for gathering subjective evidence, validating documented controls, and identifying procedural gaps.

  • System/Asset Visibility
  • Operational Continuity (DR)
  • Change Management
  • Safety/Cyber Integration

Critical Interview Protocol

Interviews are structured to assess process maturity. Below are key question areas targeted at system owners and managers.

I. System and Asset Visibility

Key Probe: Do you maintain a complete, current asset inventory that tracks all COTS software, custom code versions, and firmware for URDI/FDP components?

Goal: Assess maturity of asset management.

II. Operational Continuity & Resilience

Key Probe: What is the Maximum Acceptable Downtime (MAD) for the FDP and URDI systems, and how recently have full Disaster Recovery (DR) procedures been tested?

Goal: Validate resilience and test fidelity.

III. Change and Configuration Management

Key Probe: How is configuration integrity verified immediately after a change? Are File Integrity Monitoring (FIM) systems used?

Goal: Assess change control and config drift detection.

IV. Network and Protocol Security

Key Probe: What compensating controls ensure the authenticity and integrity of data streams using protocols known to lack built-in security (e.g., ASTERIX, ADS-B)?

Goal: Identify controls for insecure-by-design protocols.

VI. Safety/Cyber Integration (DO-326A Context)

Key Probe: Has a formal Security Risk Assessment Process (SRAP) been completed, explicitly mapping cyber threats to potential operational safety hazards?

Goal: Determine if cyber risk is tied to operational safety.

To ensure comprehensive coverage, the assessment uses three system-specific "playbooks." These detail the repeatable technical audit steps for the most critical parts of the LETVIS architecture. Select a tab below to explore the specific audit focus for each area.

Focus: Segmentation & Protocol Integrity

This playbook protects the integrity of surveillance and flight data transmitted over the network.

  • Validate Segmentation: Review firewall/router rules to confirm strict logical separation between the business (IT) and operational (OT) networks.
  • Passive Data Flow Mapping: Analyze PCAP data to map actual communication patterns and detect undocumented connections.
  • Protocol Efficacy Review: Target ASTERIX and ADS-B traffic to find compensating controls (e.g., protocol-aware IDS) that inspect for spoofing or injection.
  • Device Hardening: Review switch/router configs for secure management (SSH, MFA) and strict Access Control Lists (ACLs).

Focus: COTS System Hardening

This playbook focuses on the COTS UNIX/Linux operating systems that form the backbone of LETVIS.

  • Principle of Least Functionality: Use Ansible (check mode) to verify that all unnecessary services (daemons) and tools are removed or disabled.
  • User and Privilege Audit: Review system files to audit all local user accounts, verify strong password policies, and ensure least privilege is enforced.
  • Log Management Validation: Confirm comprehensive logging (auditd, Syslog) is enabled and logs are forwarded to a central aggregator.
  • Integrity and Patch Status: Review FIM logs for unauthorized changes and correlate with Nessus (Plugin 66334) to confirm patches are fully enabled.

Focus: Safety-Critical Data Integrity (URDI & FDP)

The URDI and FDP are the repositories of safety-critical data. This playbook prioritizes controls that protect this data from corruption.

  • Data Integrity Assurance: Review input validation mechanisms on the URDI to verify how the system handles malformed or malicious data packets.
  • Application Access Control: Audit file permissions on the `fdp 11` and `fddsup` directories, as unauthorized modification is a direct safety threat.
  • Redundancy/Failover Verification: Review failover logs and interview managers regarding recent failover testing to ensure redundancy functions under stress.
  • Application FIM Review: Specifically target FIM logs for the core FDP binaries to detect any code alteration or configuration corruption.

A mature assessment must look beyond immediate technical findings. The plan identifies four critical areas—often missed in standard IT audits—that are essential for the security of critical infrastructure. Addressing these gaps is fundamental to building long-term resilience.

1. Safety & Airworthiness Integration

The most significant gap. A vulnerability's risk *must* be scored by its maximum credible operational safety impact (per DO-326A), not just its CVSS score. A compromise to data integrity (e.g., in the URDI) is a direct safety hazard.

2. External Interface Security

The plan must assess the security of external data feeds, especially broadcast protocols like ADS-B, which lack authentication. A hardened URDI can still be compromised by corrupted data if input validation at the boundary fails.

3. Physical & Environmental Security

Physical security is a foundational OT control. The assessment must passively observe and verify physical access controls to server rooms, network closets (TAPs), and control consoles, as this is the simplest bypass for digital defenses.

4. Policy & Governance Gaps

Technical failures are often symptoms of policy failures. The plan must identify gaps in security governance, such as a lack of defined metrics, insufficient OT security training, and no commitment to a continuous assessment cadence.

The final deliverables of the assessment are a safety-weighted risk register and a set of actionable recommendations. The goal is to provide a clear, prioritized roadmap for improving the security posture of the LETVIS system, with an emphasis on systemic and sustainable resilience.

Risk Prioritization Matrix

Risk is scored by linking the likelihood of a threat to its maximum *operational safety impact*, prioritizing safety hazards above all else.

Risk Level Criteria Deadline
CRITICAL High Likelihood & Catastrophic Operational Impact (Loss of separation, flight hazard). Immediate (72h)
HIGH Medium Likelihood & High Impact (Prolonged service disruption, data corruption). 30 days
MODERATE Medium Likelihood & Medium Impact (Policy violation, config drift). 90 days
LOW Low Likelihood & Low Impact (Documentation gaps, minor hardening deficit). 180+ days

Actionable Recommendations

The final report will focus on strategic recommendations for systemic improvement.

  1. Mandate Safety/Cyber Integration: Formally implement the DO-326A/DO-355A risk process (SRAP), linking all cyber vulnerabilities to their maximum operational safety consequence.
  2. Implement Compensating Controls: Deploy protocol-aware Network Detection & Response (NDR) tools (e.g., Zeek) to monitor insecure-by-design protocols like ASTERIX and ADS-B for spoofing.
  3. Establish Configuration Baselines: Define and document the "known good state" for all UNIX/Linux systems and use FIM tools to continuously monitor for configuration drift.
  4. Strengthen Patch Validation: Update patch management procedures to *require* verification using credentialed scan data (e.g., Nessus 66334) to ensure patches are fully enabled, not just installed.
  5. Transition to Continuous Monitoring: Move from periodic "snap-shot" assessments to a continuous security improvement framework with regular DR testing and ongoing staff training.
