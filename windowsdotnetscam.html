Anatomy of a Tech Support Scam: The Azure Blob Storage Exploit

Date: November 26, 2025 | Topic: Infrastructure Abuse & Phishing

Modern tech support scams have evolved beyond simple cold calling. They now rely on complex "Living off the Land" (LotL) techniques, utilizing legitimate cloud infrastructure to bypass security filters and gain victim trust. This report analyzes a specific campaign utilizing Microsoft Azure's Blob Storage to host "Browser Locker" (Browlock) pages.

1. The Artifacts

The following Indicators of Compromise (IoCs) were identified in this specific campaign. The campaign utilizes a dual-threat mechanism: a high-reputation URL hosting a malicious payload.

Observed Malicious URL: xxxjkmajns7y4e.z13.web.core.windows.net
Associated Call Center Number: +1 (855) 568-3520

2. Infrastructure Analysis: Why "windows.net"?

The success of this scam relies heavily on the domain structure. The URL web.core.windows.net is not a spoofed domain; it is a legitimate endpoint provided by Microsoft for Azure Blob Storage static websites.

The URL Breakdown

To understand the exploit, we must dissect the URL syntax:

[xxxjkmajns7y4e] . [z13] . [web.core.windows.net]
       |             |              |
Account Name      Zone/    Root Azure Domain
(Attacker Ctrl)   Cluster  (High Reputation)
  • The Root (web.core.windows.net): This is trusted by browser filters (SmartScreen, Safe Browsing) because it hosts millions of legitimate business applications.
  • The Account Name (xxxjkmajns7y4e): The attacker creates a free or low-cost Azure Storage account. They can name this whatever they want. In this case, a random string is used to avoid detection algorithms that might flag keywords like "support" or "alert."
  • The Subdomain Takeover/Abuse Vector: While often referred to as "Subdomain Squatting," this is technically Service Abuse. The attacker provisions a legitimate resource. However, "Dangling DNS" takeovers are also possible here if a legitimate company deletes their Azure resource but leaves a CNAME record pointing to it. Attackers scan for these empty pointers and register the matching Azure account name to "hijack" the subdomain.

3. The "Trust Chain" Exploitation

The primary goal of using Azure infrastructure is Reputation Hijacking. Security mechanisms and human psychology are exploited in three ways:

  1. SSL Validity: Because the site is hosted on Microsoft's own servers, it is served with a valid wildcard SSL certificate issued by Microsoft. The "Padlock" icon appears in the browser, falsely signaling safety to the victim.
  2. Domain Whitelisting: Corporate firewalls and consumer antivirus software often whitelist *.windows.net to prevent breaking legitimate update services or business tools.
  3. Visual Authenticity: When a user sees a "Windows Security" warning coming from a URL containing "windows.net," the cognitive dissonance is reduced. The URL reinforces the fake narrative.

4. The Payload: "Browlock" Scripts

Upon visiting the URL, the static HTML page executes JavaScript designed to freeze the browser experience, forcing the user to call the support number (855-568-3520).

Common techniques utilized in the source code of this specific page type include:

  • History Looping: Manipulating the browser history API to prevent the "Back" button from working.
  • Cursor Trapping: Using full-screen API abuse to hide the mouse cursor or restrict it to the fake alert box.
  • Infinite Loops: Spawning unlimited alert dialogs (alert() or confirm() loops) that reappear instantly if dismissed.

5. Conclusion

The campaign utilizing xxxjkmajns7y4e.z13.web.core.windows.net represents a shift from compromised WordPress sites to legitimate cloud infrastructure. By abusing the democratized nature of cloud storage, scammers inherit the trust of the platform provider (Microsoft), making detection and blocking significantly more difficult for automated systems.
